# AniSync 配置样例

AniSync 的目标是**让你不用打开 ANI-RSS 的 WebUI 加订阅**：它自己扫出现在有什么番剧在放，
按你的偏好挑好主 RSS 与副 RSS，写回实例。这里放的就是"偏好"的几份现成答案。

## 目录里有什么

主配置（复制其中一份，改掉 `instances` 就能跑）：

| 文件 | 适合谁 | 一句话 |
| --- | --- | --- |
| [01-中文优先.yaml](01-中文优先.yaml) | 大多数人 | 简日内嵌 > 简繁内封 > 繁日内嵌，副 RSS 用放流组 |
| [02-收藏党-蓝光内封.yaml](02-收藏党-蓝光内封.yaml) | 等 BD、要软字幕 | 蓝光/HEVC 10bit/内封优先，**不挡合集** |
| [03-生肉原声.yaml](03-生肉原声.yaml) | 自己压、要日语音轨 | 生肉/多语优先，副 RSS 用英文放流组的 MultiSub |
| [04-全自动追番.yaml](04-全自动追番.yaml) | 想彻底撒手 | 在 01 的基础上打开自动发现，每小时自己扫一遍 |

白名单与黑名单（**单独的文件**，主配置只留引用，换口味不用动主配置）：

| 文件 | 是什么 |
| --- | --- |
| [standby.yaml](standby.yaml) | **白名单**：副 RSS 的放流组排名。没在这里点过名的组，一律不进副 RSS |
| [standby-raw.yaml](standby-raw.yaml) | 白名单变体：生肉向排序（英文放流组的 MultiSub 排前面），03 号用它 |
| [deny.yaml](deny.yaml) | **黑名单**：明确不要的组，命中即整个剔除 |

参考资料：

| 文件 | 用途 |
| --- | --- |
| [groups.md](groups.md) | 真实数据统计出来的组清单：谁在发、发什么语言、什么封装 |

**四份主配置都引用这两个文件**（03 号引用 `standby-raw.yaml`），所以复制的时候三个文件一起拿：
`config.yaml` + `standby.yaml` + `deny.yaml`，放在同一个目录里。相对路径按主配置所在目录解析。

## 三步走

```bash
AniSync init                  # 或者直接复制一份样例过来
AniSync check                 # 校验配置 + 测试实例连通性（先跑这个，别跳过）
AniSync plan                  # 只看要改什么，不写任何东西
AniSync sync -y               # 确认无误再执行
```

想试自动发现（04 号样例那套），先跑只读的两条：

```bash
AniSync discover              # 现在有什么番剧在放（不碰实例，没配实例也能跑）
AniSync plan --discover       # 哪些是实例里没有的、会新增什么
```

## 让 AI 帮你改

样例写成了「一段一段带注释」的样子，就是为了能整段丢给 AI 改。**把 `groups.md` 一起给它**，
它才知道有哪些组可选、组名怎么写。

可以直接这样问：

> 这是 AniSync 的配置样例和组清单。我只看简体中文内嵌，不要繁体；字幕组只要桜都、喵萌奶茶屋、
> 北宇治；副 RSS 要能覆盖每集的放流组。帮我把 rules.primary 重排一下，priority 从 10 开始，
> 每 10 一档。顺便帮我加几条 deny，挡掉国漫和日剧。

几个要点：

- **一定要把 `groups.md` 一起给它**，否则它会凭印象编组名，写出来匹配不到东西
- 让它**只改 `rules` 段**，`instances` / `listen` / `sync` 这些别动，避免把密钥格式改坏
- 改完让它说明**每条规则的 `priority` 为什么是这个值**，你才好继续调
- 改完自己跑一遍 `AniSync check`：正则写错了这一步就会报出来

## 最常改的 5 个地方

**1. 偏好顺序 —— `rules.primary` 的 `priority`**
数字越小越优先，第一条命中的决定优先级。想捧谁就调小，想踩谁就调大。

**2. 匹配对象 —— `match` 是正则，匹配「字幕组名 + 最近的资源标题」**
所以语言类型和组名写在同一个列表里。写组名时把简繁两种写法都写上
（`雪飄|雪飘`），因为同一个组在不同站点上的名字可能不一样。

**3. 作用域 —— `scope`**
`main` = 只参与挑主 RSS，`standby` = 只参与挑副 RSS，`both` = 两边都参与。
典型用法：中文组写 `main`，放流组写 `standby`。

**副 RSS 是「点名制」**：只有被 `scope: standby` 规则点过名的组才会进副 RSS，
没点名的一律不要。不点名就按发布条数兜底的话，会被搬运组和实例侧的伪组名刷满 ——
实测里 `geckyzz`、`生肉/不明字幕`、`20190912`、`마신` 这些全挤进来过。

**4. 白名单 —— `standby.yaml`**
副 RSS 的放流组排名单独一个文件，主配置只留一行引用：

```yaml
rules:
  maxStandby: 1              # 保留几条副 RSS；默认 1，想全收就调大
  primaryFiles: [standby.yaml]
```

`standby.yaml` 里就是一组 `scope: standby` 规则，**顺序就是 `priority`**：

```yaml
- {name: LoliHouse, match: '(?i)lolihouse|萝莉屋', priority: 10, scope: standby}
- {name: Nix-Raws,  match: '(?i)nix-raws|nc-raws', priority: 20, scope: standby}
- {name: ANi,       match: '(?i)\bani\b|baha',     priority: 30, scope: standby}
- {name: ToonsHub,  match: '(?i)toonshub',         priority: 40, scope: standby}
- {name: Erai-raws, match: '(?i)erai-raws',        priority: 50, scope: standby}
```

换口味只改这个文件，主配置一个字都不用动：

| 你想要 | 怎么改 |
| --- | --- |
| LoliHouse > Nix-Raws > ToonsHub | 把 ANi、Erai-raws 两行删掉 |
| Nix-Raws > ToonsHub | 只留这两行 |
| 只要 ToonsHub | 只留 ToonsHub 一行 |
| 所有版本都收 | 把主配置的 `maxStandby` 改成 3，下面点过名的组会按顺序依次填进去 |

**5. 黑名单 —— `deny.yaml`**
明确不要的组单独一个文件，命中即整个剔除。这比调 `priority` 更狠：
调 `priority` 只是排后面，`deny` 是直接不要。

```yaml
rules:
  denyFiles: [deny.yaml]
```

```yaml
- {match: '(?i)kirara ?fantasia|黒ネズミたち', why: 生肉搬运刷榜，会占掉副 RSS 位置}
- {match: '(?i)jmax',      why: 聚合发布者，条目里混着多个组}
- {match: '(?i)skymoon',   why: 不要的组}
- {match: '(?i)^toc\b',    why: 不要的组（^ 锚定在组名开头，不会误伤标题里带 toc 的）}
- {match: '沸羊羊|沸班亚马', why: 不要的组（同一家的两个名字）}
- {match: '生肉|不明字幕',   why: 认不出字幕语言的占位条目}
```

真实数据支撑：`Kirara Fantasia` 有 2833 条样本但语言标记为 **0**，标题实际是 `[黒ネズミたち]`
的生肉搬运 —— 不挡的话它会靠「发布条数」的兜底排序刷满副 RSS（实测十条副 RSS 里占八条）。
`沸羊羊字幕组`（蜜柑 id 4729）和 `沸班亚马制作组`（id 672）是同一家的两个名字，两个都要写。

「不要合集」「不要 720p」这类个人口味写在主配置的 `rules.deny` 里，不塞进共享文件 ——
收藏党恰恰要合集，共享文件里放这个会打架。

内联的 `primary` / `deny` 仍然有效，顺序是「内联在前、文件按声明顺序在后」。
文件路径写错或格式不对会**直接报错**，不会静默跳过让你以为规则生效了。

**6. 季度与偏移 —— `targets`**

常规做法是**提前把 bgm 链接贴进来**，而不是先建订阅再回头引用它：

```yaml
targets:
  - bgmId: "https://bgm.tv/subject/665390"  # 链接和纯数字都认，贴哪一栏都行
    season: 2                               # 一般只写季度
    # offset / standbyOffset 留空 —— 集偏移得看是哪个组才写
```

- **`season` 按番剧给一个值**：该番剧的所有订阅共用它，实例里已有的订阅同样生效，不必逐个改
- **集偏移得看是哪个组才写**。不同字幕组的 RSS 起数不一样（有的从第 13 集接着数，有的从 1 重新数），
  所以除非你确定这条订阅的主 RSS 是哪个组、它怎么数集，否则留空更安全
- `offset` 管主 RSS，`standbyOffset` 管副 RSS，两者分开给
- **留空 = 不碰**：ANI-RSS 会按每个 RSS 的实际集数自动推断偏移，多数番剧根本不用写

`bgmId` 栏可以贴 `https://bgm.tv/subject/665390` 这样的链接，程序会自己取出 `665390`；
贴在 `title` 栏也会被认出来（认出后 title 会被清空，避免退化成标题模糊匹配）。

## 本季新番（`discover` 段）

设置页里叫「本季新番」：一屏列出当季在放送的番剧，勾选后一键加进订阅。
命令行那边叫 `discover`，是同一套逻辑。

| 字段 | 说明 |
| --- | --- |
| `enabled` | 打开自动添加。命令行 `--discover` 等价 |
| `sources` | 发现来源，默认 `[yuc]` |
| `limit` | 单次最多新增多少条，默认 50。第一次跑别设太大 |
| `enable` | 新加出来的订阅是否**直接启用**。留空 = false，只建订阅不下载 |
| `exclude` | 标题黑名单正则，命中就不加 |
| `japanOnly` | 只有 `bangumi-calendar` 用得到：只保留日本 TV 番剧与剧场版，默认 true |
| `days` | 只有 `animegarden` 用得到：「首播日期在最近多少天内」算在放，默认 180 |
| `bgmUser` | 只有 `bangumi-collections` 用得到：Bangumi 用户名或 uid |

**为什么默认用 `yuc`。** Bangumi 放送表把国漫、美漫、OVA、网络短片全混在一起，
而且**不带地区与平台** —— 要筛干净只能逐条查条目详情，一季 110 次请求：

| 放送表里的条目 | 平台 | 地区标签 | |
| --- | --- | --- | --- |
| 航海王 | TV | 日本 | ✓ |
| 大王饶命 第三季 | WEB | 中国 | ✗ |
| 极恶老大 第三季 | WEB | 欧美 | ✗ |
| 极道寿司次郎！ | TV | 美国 | ✗ |
| 黑暗召唤师…迷你动画剧场 | WEB | 日本 | ✗ 平台不对 |

[Yuc](https://yuc.wiki/) 的季度页本身就是一份人工整理过的日本番剧表。
拿它定「这一季有什么」，再让 Bangumi 只负责补 `bgmId`，两边各干各擅长的事。

**匹配走日文原名，不是中文名。** 中文译名是各家自己的写法，实测拿它去对放送表
只有 46% 命中；日文原名 88%（`Season2` / `第2クール` / `Ⅱ` / `II` 这些写法差异
在比对前会先归一化）。剩下 12% 靠 Bangumi 检索兜底。

另外三个来源仍然可用，只是不进默认值：

| 来源 | 什么时候用 |
| --- | --- |
| `bangumi-calendar` | 不想依赖 GitHub（Yuc 归档放在 raw.githubusercontent.com）。自带 `bgmId` 但混着国漫美漫 OVA，靠 `japanOnly` 过滤 |
| `animegarden` | 只列出**真的有字幕组在做**的番剧。怕把一堆没人做的番灌进实例时用它（配合 `days`） |
| `bangumi-collections` | 扫某个 Bangumi 用户的「在看」，也就是「按我的追番列表建订阅」。要填 `bgmUser`，收藏需公开 |

发现出来的条目不写季度与偏移 —— 交给 ANI-RSS 自己推断，这正是「不用打开 ASS」的前提。

## 组清单怎么用

[groups.md](groups.md) 分五段，每段一张表：

- **字幕组** —— 标题里有语言标记的，配置里主要用这些
- **压制组** —— 走 BD / HEVC / 10bit 路线的
- **搬运 / 聚合发布** —— 产量极高但认不出语言标记，多半是生肉搬运。默认规则下它们会刷满副 RSS
- **样本太少** —— 出现次数个位数，用之前先自己点进去确认
- **Nyaa 放流组** —— 按「有单集特征的标题条数」排序，标了「国漫」的是华语原声，不是日本番剧

两个必须知道的事实：

1. **AnimeGarden 注册了 727 个组，但最近 10000 条资源里只有 63 个组真的在发。**
   配置里优先写清单里出现过的组名，注册表里那些长期不更新的组写了也匹配不到东西。
2. **组名的写法要以清单为准。** 同一个组在 dmhy / 萌番组 / 蜜柑上的名字可能不同，
   简繁写法也常常并存（`百冬練習組` / `百冬练习组` 会被当成两个组）。

## 常见坑

**规则顺序写反了。** `简繁日内封` 的标题里同时含有「繁日」两个字，所以 `简繁` 规则
必须排在 `繁日` 规则**前面**，否则 `简繁日内封` 会先被 `繁日` 规则吃掉。

**`deny` 写太宽。** 比如 `BDRip` —— 周更观看不想要它，收藏党恰恰要它。
01 号样例挡了合集，02 号故意没挡，就是这个原因。

**以为留空 = 设成 0。** `sync.season` / `offset` / `standbyOffset` 和 `targets` 里的同名字段，
**留空是「不碰」，写 0 是「覆盖成 0」**。这两个含义完全不同，别写错。

**副 RSS 要选几乎每集都发的组。** 副 RSS 的作用是主 RSS 缺集时顶上，选一个三天打鱼两天晒网的组
等于没配。

**代理。** 从国内直连 `nyaa.si`、`api.bgm.tv` 和封面图床 `lain.bgm.tv` 通常不通。
设置页的「网络与代理」里填一个就行，也可以直接改配置里的 `proxy:`，或者设环境变量 `ANISYNC_PROXY`。
它同时管站点数据、Bangumi 搜索和封面图。`api.animes.garden` 一般可以直连。

**在设置页改配置不会丢注释。** AniSync 保存时走的是「把新值合并回原文件的节点树」，
注释、键序、`{...}` 一行写法都会留着，只有空行和行内注释的对齐会被归一化。
所以样例里那些注释可以放心留着当文档，改完配置再看还是原样。

不过设置页只认识**主配置**：外置的 `standby.yaml` / `deny.yaml` 它不编辑，
只会显示「另有 N 条来自 xxx.yaml」。要改白名单和黑名单，直接改那两个文件。
