# AniSync 配置样例

AniSync 的目标是**让你不用打开 ANI-RSS 的 WebUI 加订阅**：它自己扫出现在有什么番剧在放，
按你的偏好挑好主 RSS 与副 RSS，写回实例。这里放的就是"偏好"的几份现成答案。

## 目录里有什么

追新番有四种情况，各一份主配置：

| 文件 | 主 RSS | 副 RSS | 什么时候用 |
| --- | --- | --- | --- |
| [01-只追放流.yaml](01-只追放流.yaml) | 放流组 | 另一个放流组 | 不要中文字幕，只要第一时间拿到片子 |
| [02-只要字幕组.yaml](02-只要字幕组.yaml) | 按版本挑中文字幕 | **不配** | 只认中文软字幕，缺集宁可等 |
| [03-字幕组加放流.yaml](03-字幕组加放流.yaml) | 字幕组（按版本） | 放流组 | 想要中文字幕，又不愿意为了等字幕组漏集 |
| [04-全收.yaml](04-全收.yaml) | 谁都行 | 其余全部 | 不挑，除了黑名单全都要 |

规则文件（**主配置只留引用，换口味不用动主配置**）：

| 文件 | 是什么 |
| --- | --- |
| [subs.yaml](subs.yaml) | 字幕**版本**分档，`scope: main`，`in: title` —— 简繁日内封 > 简日内嵌 > 繁日内嵌 |
| [raws.yaml](raws.yaml) | 放流**组**排名，`scope: both` —— 有中文的 ToonsHub / Nix-Raws 优先，其余同档 |
| [all.yaml](all.yaml) | 「谁都行」，`scope: both` —— 给 04 号全收用，也是任何偏好名单的兜底 |
| [deny.yaml](deny.yaml) | 黑名单，命中即整个剔除 |

**01 要 `raws.yaml` + `deny.yaml`；02 要 `subs.yaml` + `deny.yaml`；
03 要 `raws.yaml` + `subs.yaml` + `deny.yaml`（顺序就是 `raws.yaml` 在前）；
04 要 `all.yaml` + `deny.yaml`。**
复制的时候一起拿，放在同一个目录里，相对路径按主配置所在目录解析。

## 三步走

```bash
AniSync init                  # 或者直接复制一份样例过来
AniSync check                 # 校验配置 + 测试实例连通性（先跑这个，别跳过）
AniSync plan                  # 只看要改什么，不写任何东西
AniSync sync -y               # 确认无误再执行
```

四份样例都打开了自动发现（`discover.enabled: true`），所以 `sync` 会顺手把当季没订阅的番
加进去。**加出来的订阅默认是停用的**（`discover.enable: false`），不会一上来就触发下载。
先跑只读的两条看一眼：

```bash
AniSync discover              # 现在有什么番剧在放（不碰实例，没配实例也能跑）
AniSync plan --discover       # 哪些是实例里没有的、会新增什么
```

## 组名怎么写（只在按组排的规则里用得到）

**写 ANI-RSS 选组界面上显示的那个名字就行。**

只有 `raws.yaml` 这种「按组排」的规则需要写组名；`subs.yaml` 按版本排，里面一个组名都没有。

AniSync 拿到的候选本来就带这个名字（`anibt` / `animegarden` / `mikan` 走实例接口，
实例给什么名字就是什么名字）。同时它还会把资源标题方括号里印出来的名字一并当成
这个组的别名 —— 所以显示名和种子名对不上时，**写哪一个都能命中**：

```yaml
# 下面两条命中同一个组，写一条就够了
- {name: 猎户发布组, match: '(?i)猎户发布组', priority: 475, scope: both, in: group}
- {name: 猎户发布组, match: '(?i)猎户压制部', priority: 475, scope: both, in: group}
```

别名是跟着候选从标题里现算的，不用人去维护，也不用逐条核对。

> 为什么能这样：`in: group` 让这条规则只看组名。组名这一侧 = 候选的显示名
> + 标题方括号里的名字（`internal/source/source.go` 的 `GroupAliasesFromTitles`，
> 与 ANI-RSS 的 `ItemsUtil.getSubgroup()` 同源）。
> 想看某个候选到底有哪些名字，跑 `AniSync probe -site anibt -bgm <bgmId>`。

### 简繁两种字形要各写一个

`绿茶字幕组` 和 `綠茶字幕組` 是同一个名字的两种字形，别名机制对不上（字不一样），
所以规则里得写全：`match: '(?i)绿茶字幕组|綠茶字幕組'`。
`raws.yaml` 里那段「中文标记」也是这个道理 —— `简繁|簡繁` 两种字形都列上了。

### 短名字锚在开头

`ANi`、`Judas`、`ASW`、`DKB` 这种名字很短，写 `(?i)ani` 有可能蹭到别的组名。锚在开头就不会：

```yaml
- {name: ANi, match: '(?i)^ani\b', priority: 450, scope: both, in: group}
```

以前这里得写成 `^ani\b|\[ani\]`，还要在注释里解释「为什么不能写 `\bani\b`」——
那是因为规则当时连资源标题一起匹配，作品名「Ani ni Tsukeru Kusuri wa Nai」里的 `Ani`
会把别的组认成 ANi。`in: group` 之后标题根本不参与匹配，这个坑就不存在了。

## 最常改的地方

**1. 字幕按版本排 —— `subs.yaml`**
`subs.yaml` 里没有组名，只有三个版本档：`简繁日内封`(100) > `简日内嵌`(200) > `繁日内嵌`(300)。
它读的是资源标题里的版本标签（`[简繁内封]` / `[简日内嵌]` / `[CHS&CHT&JP&EN&KO]`），
所以「哪个组做哪个版本」不用你维护 —— 组换了版本，下一次爬取自动跟上。

为什么不再抄一张组名表：一个组做哪个版本是它自己的事，而且会变。手抄的表一旦过时，
**不会报错，只会安静地挑错组**。版本标签就印在标题里，直接读它更准。

**2. 放流组按「有没有中文」分档 —— `raws.yaml`**
第一档（400）是**有中文**的放流组：ToonsHub = Nix-Raws。
「有中文」是逐部番剧判的，不是给组贴死标签 —— 规则读的是这个组**这部番剧**最近 12 条标题：

```yaml
# 组名和标题一起看（in: any），两个条件必须同时成立
- {name: ToonsHub·有中文, match: '(?is)toonshub.*(?:简繁|簡繁|…|\bCH[ST]\b)', priority: 400, scope: both, in: any}
```

于是：只有 Nix-Raws 有中文时，ToonsHub 掉到 500，Nix 上；两个都有就同档比条数；
两个都没有就都掉到 500，谁条数多谁上（AniSync 没有「每集几点放」的数据，判定不了真速度，
只能用发布条数近似 —— 这一点文件里也写明了）。

**3. 顺序决定谁先被匹配 —— `primaryFiles` 的顺序**
匹配是「**按声明顺序，第一条命中的生效**」，不是「按数字最小的生效」；数字只决定同一档内的先后。
所以 03 号样例把 `raws.yaml` 写在 `subs.yaml` **前面**：
点过名的放流组先落到 400/450/500，不会再往下掉进字幕的版本档。

为什么非这样不可：Nix-Raws 的标题里写着 `[简繁内封]`，光看版本它跟 LoliHouse 是同一档；
不先把放流组挑出来，它会靠「发布条数多」在主 RSS 上挤掉字幕组 —— 实测就是这么发生的
（幼女战记 / 擅长逃跑的殿下 / 感谢对战 等 6 部）。

**4. 站点顺序 —— `sources.order`**
`anibt` 和 `animegarden` 是**两批不同的组**，不是一层套一层，两个都开着才有完整的字幕组覆盖。
实测同一批 121 部番剧：只在 `animegarden` 出现的「番剧 × 字幕组」组合有 111 个
（喵萌奶茶屋 16、猎户发布组 9、悠哈璃羽字幕社 7、爱恋字幕社 5、极影字幕社 4 …），
只在 `anibt` 出现的多是放流组（ToonsHub 60 部）。**只开 anibt 会让一大批番剧退回到放流组当主。**
`nyaa` 补 Erai-raws / SubsPlease / Judas 这些只在那边的放流组。

**5. 作用域 —— `scope` 与 `in`**
`scope` 决定规则参与挑哪一侧：`main` = 只参与挑主 RSS，`standby` = 只参与挑副 RSS，
`both` = 两边都参与。`subs.yaml` 用 `main`、`raws.yaml` 用 `both`，
所以副 RSS 只会在放流组里选，主 RSS 优先给字幕组。

`in` 决定规则匹配什么：`group` = 只看组名（排组用这个），`title` = 只看资源标题（排版本用这个），
`any` = 两者一起看（「哪个组」+「有没有中文」这种两条件组合必须用它）。
**不写 `in` 就是 `any`** —— 那是分轴之前的老行为，
所以已有的配置不会因为升级而改变挑选结果；新写的规则建议都显式写清楚。

**副 RSS 是「点名制」**：只有被 `scope: standby` 或 `scope: both` 规则点过名的组才会进副 RSS。
不点名就按发布条数兜底的话，会被搬运组和实例侧的伪组名刷满 ——
实测里 `geckyzz`、`生肉/不明字幕`、`20190912`、`마신` 这些全挤进来过。
所以 **02 号样例故意一条 standby 规则都不写**，副 RSS 就是空的；
**04 号样例反过来**，用 `all.yaml` 里那条 `.+`（命中所有组名）把副 RSS 收满。

**6. 每条订阅留几条副 RSS —— `maxStandby`**
默认 1。想「所有版本都收」就调大：04 号样例给的是 12 —— 实测 121 部番剧里，
两个站点加起来每部中位数 8 个候选、最多 24 个，按组名去重后需要 12 条上限的只有 2 部。
别盲目调大：ANI-RSS 抓每个副 RSS 之间要 `sleep 1` 秒（`ItemsUtil.java:54`）。

**7. 黑名单 —— `deny.yaml`**
比调 `priority` 更狠：调 `priority` 只是排后面，`deny` 是直接不要。
文件里有一条已经踩过的坑：**不要写 `(?i)skymoon`** ——
`天月動漫發佈組` 的种子名就是 `Skymoon-Raws`，挡 skymoon 会把它一起挡掉。
还有一条日期伪组名（`^\d{8}\b` / `^\d{4}\.\d{1,2}\.\d{1,2}\b`）：
Nyaa 没有「组」这一维，AniSync 是拿标题开头的方括号当组名，`[20230125]` 会被当成一个组。

「不要合集」「不要 720p」这类个人口味写在主配置的 `rules.deny` 里，不塞进共享文件。

**6. 季度与偏移 —— `targets`**

```yaml
targets:
  - bgmId: "https://bgm.tv/subject/665390"  # 链接和纯数字都认，贴哪一栏都行
    season: 2                               # 一般只写季度
    # offset / standbyOffset 留空 —— 集偏移得看是哪个组才写
```

- **`season` 按番剧给一个值**：该番剧的所有订阅共用它，实例里已有的订阅同样生效
- **集偏移得看是哪个组才写**。不同字幕组的 RSS 起数不一样（有的从第 13 集接着数，
  有的从 1 重新数），除非你确定这条订阅的主 RSS 是哪个组、它怎么数集，否则留空更安全
- `offset` 管主 RSS，`standbyOffset` 管副 RSS，两者分开给
- **留空 = 不碰**：ANI-RSS 会按每个 RSS 的实际集数自动推断偏移，多数番剧根本不用写

## 让 AI 帮你改

样例写成了「一段一段带注释」的样子，就是为了能整段丢给 AI 改。
**把 `subs.yaml` / `raws.yaml` 一起给它**，它就能照着你现有的口味改。
可以直接这样问：

> 这是 AniSync 的规则文件。字幕我要的顺序是 简繁日内封 > 简日内嵌 > 繁日内嵌，
> 但「简繁内嵌」我想要单独排在简日内嵌后面；放流组我要 ToonsHub = Nix-Raws > Erai-raws，
> 前提是它们得带中文，都没中文就谁快谁上。帮我把 subs.yaml 和 raws.yaml 改一下。
> 顺便加几条 deny，挡掉国漫。

几个要点：

- **加新组时让它只在你给它的名单里挑**，别自己编 —— 编出来的名字不报错，只是永远匹配不到。
  要加新组，先在 ANI-RSS 的选组界面上确认它叫什么，把那个名字给它
- **版本标签可以放心让它自己写** —— 那些标签是真实标题里印着的（`简繁内封` / `简日内嵌` /
  `CHS&CHT&JP&EN&KO` / `GB` / `BIG5`），不是编出来的
- 让它**只改规则文件**，`instances` / `listen` / `sync` 这些别动，避免把密钥格式改坏
- 改完自己跑一遍 `AniSync check`：正则写错了这一步就会报出来

## 本季新番（`discover` 段）

设置页里叫「本季新番」：一屏列出当季在放送的番剧，勾选后一键加进订阅。
命令行那边叫 `discover`，是同一套逻辑。

| 字段 | 说明 |
| --- | --- |
| `enabled` | 打开自动添加。命令行 `--discover` 等价 |
| `sources` | 发现来源，默认 `[yuc]` |
| `limit` | 单次最多新增多少条，默认 50。第一次跑别设太大 |
| `enable` | 新加出来的订阅是否**直接启用**。样例里是 false，只建订阅不下载 |
| `exclude` | 标题黑名单正则，命中就不加 |
| `japanOnly` | 只有 `bangumi-calendar` 用得到：只保留日本 TV 番剧与剧场版，默认 true |
| `days` | 只有 `animegarden` 用得到：「首播日期在最近多少天内」算在放，默认 180 |
| `bgmUser` | 只有 `bangumi-collections` 用得到：Bangumi 用户名或 uid |

**为什么默认用 `yuc`。** Bangumi 放送表把国漫、美漫、OVA、网络短片全混在一起，
而且**不带地区与平台** —— 要筛干净只能逐条查条目详情，一季 110 次请求。
[Yuc](https://yuc.wiki/) 的季度页本身就是一份人工整理过的日本番剧表。
拿它定「这一季有什么」，再让 Bangumi 只负责补 `bgmId`，两边各干各擅长的事。

**匹配走日文原名，不是中文名。** 中文译名是各家自己的写法，实测拿它去对放送表
只有 46% 命中；日文原名 88%（`Season2` / `第2クール` / `Ⅱ` / `II` 这些写法差异
在比对前会先归一化）。剩下 12% 靠 Bangumi 检索兜底。

另外三个来源仍然可用，只是不进默认值：

| 来源 | 什么时候用 |
| --- | --- |
| `bangumi-calendar` | 不想依赖 GitHub（Yuc 归档放在 raw.githubusercontent.com）。自带 `bgmId` 但混着国漫美漫 OVA，靠 `japanOnly` 过滤 |
| `animegarden` | 只列出**真的有字幕组在做**的番剧。怕把一堆没人做的番灌进实例时用它（配合 `days`） |
| `bangumi-collections` | 扫某个 Bangumi 用户的「在看」，也就是「按我的追番列表建订阅」。要填 `bgmUser`，收藏需公开 |

发现出来的条目不写季度与偏移 —— 交给 ANI-RSS 自己推断，这正是「不用打开 ASS」的前提。

## 常见坑

**组名写错。** 写 ANI-RSS 选组界面上显示的名字就行，种子标题里的名字（`猎户压制部`）
也能命中。但自己编的名字**不会报错**，只是永远选不到那个组 ——
拿不准就跑 `AniSync probe -site anibt -bgm <bgmId>`，看这个番剧的候选都有哪些名字。

**短名字不锚定。** `(?i)ani` 有可能蹭到别的组名，写成 `(?i)^ani\b`。
（以前得写 `^ani\b|\[ani\]`，因为规则连资源标题一起匹配；`in: group` 之后不用了。）

**忘了文件顺序。** 匹配是「按声明顺序，第一条命中的生效」。03 号样例里
`raws.yaml` 必须写在 `subs.yaml` 前面，否则 Nix-Raws 会靠 `[简繁内封]` 混进字幕的版本档。
改 `primaryFiles` 的顺序就等于改挑选结果 —— 这是最容易踩、也最难看出原因的一个。

**`deny` 写太宽。** 比如 `BDRip` —— 周更观看不想要它，收藏党恰恰要它。
还有 `skymoon` 这种：它同时是一个大组的种子名。

**以为留空 = 设成 0。** `sync.season` / `offset` / `standbyOffset` 和 `targets` 里的同名字段，
**留空是「不碰」，写 0 是「覆盖成 0」**。这两个含义完全不同，别写错。

**副 RSS 要选几乎每集都发的组。** 副 RSS 的作用是主 RSS 缺集时顶上，选一个三天打鱼两天晒网的组
等于没配。

**代理。** 从国内直连 `nyaa.si`、`api.bgm.tv` 和封面图床 `lain.bgm.tv` 通常不通。
设置页的「网络与代理」里填一个就行，也可以直接改配置里的 `proxy:`，或者设环境变量 `ANISYNC_PROXY`。
它同时管站点数据、Bangumi 搜索和封面图。`api.animes.garden` 一般可以直连（但会限流，
连着打几百个请求会拿到 429）。

**在设置页改配置不会丢注释。** AniSync 保存时走的是「把新值合并回原文件的节点树」，
注释、键序、`{...}` 一行写法都会留着，只有空行和行内注释的对齐会被归一化。
所以样例里那些注释可以放心留着当文档，改完配置再看还是原样。

不过设置页只认识**主配置**：外置的 `subs.yaml` / `raws.yaml` / `deny.yaml` 它不编辑，
只会显示「另有 N 条来自 xxx.yaml」。要改规则，直接改那三个文件。
